# Code review — 2026-07-24

Review of M0–M3 committed code plus the uncommitted M4 work (`planes.js`,
rewritten `fins.js`). Ranked; fix bugs 1–2 before the next in-browser M4 test.

## Bugs

- [ ] **1. `fitPatch` plane offset `d` is ⅓ of its true value — BLOCKS M4.**
  `planes.js` ~line 148–156: `wSum += area[f]` sits inside the 3-vertex inner
  loop, so `wSum` ends up as 3·Σarea — but the divisor is `wSum * 3`, dividing
  by 9·Σarea while the numerator carries 3·Σ(area·projection). Every patch's
  plane lands at one-third of its real distance from the origin; the flatness
  deviation is measured against the same wrong `d`, so `dev` blows past
  `FLAT_TOL` and nearly every patch is rejected. **Symptom in browser:** "no
  flat vertical face is tall enough" on parts that obviously have them.
  **Fix (one line):** `const d = dSum / wSum;` (or move the `wSum` increment
  out of the inner loop and keep the `* 3`).

- [ ] **2. Pad + lean vector go missing on exactly the tilted-on-edge case.**
  `fins.js` ~line 304–324: `contact` is collected only from vertices of faces
  flagged `onBed`. A part tilted onto an edge — the flagship case, bed contact
  ≈ 0 — has **no** faces whose max vertex sits under `BED_EPS`, so `contact`
  is empty. Consequences: `buildPad` returns null (no pad on the part that
  most needs one); the readout (`app.js` ~418) then says "not needed" — the
  opposite of the truth; and `tip` stays null, so `scorePatches`' alignment
  term is zero and fins are not aimed at the fall direction.
  **Fix:** derive contact from welded *vertices* with z < ε (topology already
  has everything needed), not from whole-face bed classification.

- [ ] **3. Stats timing line accumulates.** `updateFinReadout` appends with
  `el('s-time').textContent += …` (`app.js` ~440). Correct when reached via
  `shade()` (which resets the line), but the mode-select, bed-pad, and
  fins-toggle handlers call `refreshFins()` directly — each toggle appends
  another "· fins N ms" without a reset.

- [ ] **4. Fit check ignores fins and pad.** `report()` (`app.js` ~329–336)
  tests only the part bbox against the build volume, but the export bakes in
  the pad, whose ellipse extends `padMargin` (4 mm) past the contact and can
  cross the plate edge on a part that "fits". Extend the fit bounds over
  `finTris`/`padTris` when fins are on.

- [ ] **5. `patchCovers` returns true for degenerate triangles.**
  `planes.js` ~198–204: a zero-area sliver gives d1=d2=d3=0, so `neg` and
  `posv` are both false → "inside". One sliver in a patch makes the coverage
  test always pass, resurrecting the tine-into-thin-air case the function
  exists to prevent. Guard: skip triangles with ~0 projected area.

- [ ] **6. Cosmetic:** STL header em-dash (`stl.js` ~27) survives the `& 0x7f`
  mask as control byte 0x14. Use a plain hyphen.

## Deviations from our own spec — need a decision

- [ ] **Wall spans the whole patch; spec says edge/corner.** FIN-SPEC:
  "place on an edge or corner, never mid-face" — but `buildFin` extrudes the
  wall across the entire patch (`fins.js` ~118, `uA..uB`) with tines every
  14 mm across the full width. On a big face that's a 100+ mm wall with
  pockmarks across the middle of the visible surface, and `FIN` has no
  `maxLen`. Consider capping wall length (proportional to height, maybe
  15–25 mm) and anchoring it at a patch *end* (a corner) rather than centered.
- [ ] **Layer-height / nozzle-width must become per-call params, not globals.**
  Roadmap already says the spec numbers derive from these inputs, but `FIN`
  hard-codes `tineH: 0.3` / `tineW: 0.5` as a module global. When the inputs
  land, don't mutate `FIN` — have `buildFins` take `{...FIN, ...overrides}`
  per call. Keeps the geometry core reusable outside this UI.
- [ ] **Watertight readout is in the roadmap's Load section but unimplemented.**
  Nearly free: `buildTopology` already builds the edge map — edges never
  paired are boundary edges; boundary-count == 0 is the badge. ~10 lines,
  good trust signal.

## Architecture (protect what's good)

The layering is right and worth defending: `overhangs.js` / `planes.js` /
`fins.js` / `writeBinarySTL` are pure geometry with zero DOM or three.js
dependencies; `app.js` is the composition root. Windings on all four solids
(wall, base, tines, pad) were checked and are correctly outward.

- [ ] **Split `app.js` BEFORE M5, not after.** 740 lines mixing scene setup,
  gizmo + click-to-lay, volume persistence, fin UI, export, drag-drop, with
  ~15 shared mutable top-levels. Draw mode adds a pointer-interaction state
  machine on top of the existing hover/press/gizmo interplay (~lines 540–585
  already juggle four states). Extract `viewer.js` (scene/camera/lights/
  plate), `orientation.js` (gizmo + face-pick), `volume.js` (presets/
  localStorage); app.js just wires them.
- [ ] **JSDoc `@typedef` for the four load-bearing shapes** (Topology,
  AnalysisResult, Patch, buildFins result). Currently prose-only contracts;
  typedefs get IDE checking with no build step.
- [ ] **`tests.html` — in-browser test page, no node needed.** Import the pure
  modules, assert on tiny synthetic meshes (cube, 45° wedge, L-face for
  `patchCovers`). Would have caught bug #1. Locks the numerical behaviors
  (45° epsilon, patch fitting) against regression.
- [ ] **Decouple `buildTopology` from three.js** — accept a raw positions
  array instead of a BufferGeometry (it only reads
  `getAttribute('position').array`).

## Feature candidates (not in the roadmap; judged worth their lines)

- [ ] **Fin material readout ("fins add ~2.3 g").** Closed solids → volume is
  a divergence-theorem sum over triangles already emitted. Services the "less
  material" claim, feeds the unverified "faster" measurement, gives
  Stabilize-vs-Coverage a visible cost axis. Highest value-per-line item here.
- [ ] **Orientation undo (Ctrl+Z).** Reset-only is harsh when click-to-lay
  picks the wrong face; quaternion stack pushed per interaction, ~15 lines.
- [ ] **Inch-unit detection.** bbox under ~5 mm → prompt "looks like inches —
  scale ×25.4?".
- [ ] **Orientation in the URL alongside `?stl=`.** A shared link reproduces
  the exact scene — bug reports, the video, and designers linking "here's how
  to print my model" (the Printables/MakerWorld wedge).
- [ ] **Screenshot button.** The red-overhang view is the most
  screenshot-able thing in the app; `canvas.toBlob` + a re-render. Organic
  sharing loop.
- [ ] **Pull the sample-model button forward from M7.** `loadURL` plumbing and
  `dev-models/` already exist; roadmap itself calls it "the difference between
  a bounce and a first export". An hour, not a milestone.
- [ ] **Export a sidecar report** (`.txt` next to the STL, or baked into the
  80-byte header + filename): what was added, intended orientation, "no
  slicer supports needed". The STL travels without us.

## Verdict on the plan itself

M4→M7 sequencing is sound (Stabilize before Coverage; permission UI before
part-modification). Placement-as-a-mode is the strongest product decision in
the docs. No structural changes recommended.
